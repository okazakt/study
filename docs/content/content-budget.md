# コンテンツ追加の文字量・構成チェック

更新：2026-11-05。ユーザー指定により、既存形式への追加はJSON中心で進め、毎回のテストスイート・全問表示・5分進行・履歴やオフラインの再確認は行わない。

## 編集用の上限

基準画面は320×844。文字数はUnicode文字数で数える。以下は新規追加の編集予算であり、既存データにある最大文字数や全端末の描画保証とは区別する。

| 表示項目 | 上限 |
| --- | ---: |
| 設問・作業指示 `task` | 40文字 |
| 問題文・本文 `prompt` | 60文字 |
| 選択肢 | 1つ30文字 |
| 対象穴の案内 `targetLabel` | 40文字 |
| 正答後の解説 `note` | 120文字 |
| 設問＋本文＋4選択肢 | 合計200文字 |

**各項目の最大値を同時に使えるわけではない。** 本文が長い場合は選択肢を短くする。従来の「合計200文字・選択肢30文字」だけでは、長い英語の返答を4つ並べた場合などの収まりを判定できなかった。

そのため文字数に加え、4列／2列、全角・半角、改行、穴の案内の有無、組合せによる行数・高さも簡易計算する。機械用の設定は [content-budget.json](content-budget.json)。現在の選択肢列数の切替条件をそのまま使用し、問題枠の高さは余白を含め330pxを編集用目安とする。推定値は描画の厳密な再現ではなく、確認対象を絞るための保守的なガード。

## 追加・修正の手順

1. 既存IDを維持し、問題・選択肢・正答・解説をJSONで追加・修正する。別解が正解にならないかは作問時に確認する。
2. 新規分だけを `node scripts/check-content-budget.mjs --file quiz-data/対象.json --batch 追加バッチ名` で確認する。これはJSON・ID・4択・文字量／構成の簡易検査であり、ブラウザやプレイを実行しない。
3. 既存想定の文字主体4択／2列4択で予算内なら、そのまま進める。全問表示やテストスイートは行わない。
4. 超過分はまず短縮・分割する。新しい画像・図・表・数式配置や、短縮後も想定外の組合せだけ、代表ケースを画面で確認する。確認した新構成は条件を記録して再利用する。

短い英単語と長い日本語は同じ文字数でも幅が異なる。画像・図がある場合には文字の上限を単独で適用せず、図の高さを含む別プロファイルで扱う。文字サイズ拡大、従来より小さい画面、表示実装の変更も別の確認対象。

進行・採点・保存・表示機能そのものを変更した場合だけ、影響範囲に応じて機能確認を行う。確認済みの既存問題を、内容追加のたびに再検証しない。

## 国語の確認済み範囲（v0.66.0・2026-11-07）

高さ推定330pxを超える追加分について代表7例、320/390×844の通常/学習集中で28表示を確認した。国語の文字だけの2列／4列について、設問21・本文36・選択肢各28・穴案内21・解説39・合計113文字以内、かつ推定高さ390px以内であれば同じ表示確認を繰り返さない。一般の文字上限は変更せず、この条件内だけ高さの例外を適用する。実測最大パネル高は416px。

条件と根拠は [content-budget.json](content-budget.json) の `reviewedTextProfiles`、[計測記録](japanese-source/layout-review.json) に保持する。図・画像・新構成や条件外は従来の手順を使う。単に確認対象を減らすために全体の上限を広げる運用はしない。

## 漢字書きの確認済み構成（v0.67.0）

`lr-parts-v1` は既存の字形選択UIを使う。左右の2部品、または左と右上下の3部品だけを対象とし、左幅40/60％、右側の上下は50/50％という確認済みのボックスに限定する。画像・別の囲み・上下全体・独体字などにこの承認を流用しない。

条件は設問0・本文34・候補各1・案内16・解説16・合計61文字以内。例文24字、語3字、読み6字までに加え、読みと語の想定幅250px以内も要求する（読みだけ6字、語だけ3字という上限を同時に使えるわけではない）。候補は1文字のBMP内の漢字・カタカナ字形。任意の図や画像フラグがある場合は引き続き確認対象。実際のボックスとフィールド値を照合し、単にプロフィール名を付けるだけでは確認を省略できない。

代表例は [表示記録](japanese-source/writing-layout-review.json)。この範囲内の新しい漢字はJSONの簡易チェックだけで追加する。既存画面・文字サイズ自体の変更は別途確認する。

長い熟語を見出しにする `japanese_definition` は、13〜14字の見出しなら説明候補各19字以内を確認済み範囲とする。候補20字以上、または見出し15字以上は同じ全体文字数内でも確認対象にする。今回のことわざの説明を短縮して収まりを確かめたもので、一般の高さ上限を緩めるものではない。
