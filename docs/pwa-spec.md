# Study Beat PWA 仕様書（仮実装）

更新日: 2026-11-01

## 目的・対象

中学生・高校生が、音楽に合わせたタップと4択クイズを通して楽しく暗記を繰り返す学習用音楽ゲーム。リズムの上達と知識の定着を別々に評価する。

既存のリズムゲーム仕様を、暗記学習用の仕様に更新し、静的PWAを追加した。中学5教科は合計3,088素材・10,558生成問題、2曲。英語優先の拡充を進めている。全学年に収録があるが、受験範囲の網羅と教科書対応は未完了。対象全体は中高生だが、高校問題データはまだ含まない。

## ゲームの流れ

1. 初回は中学／高校を選択し、教科→学年／受験用→単元を選んで開始。学校と範囲は次回へ保存する。問題・音楽データを読み込む。
2. ウォームアップ（暫定8秒）：4レーンのうち1レーンに白ノーツを流し、そのレーンをタイミングよくタップ。レーンはシャッフルする。
3. 出題：問題文と4択のパネルを手元（判定ラインの上）に表示。用語がある問題は、まず用語を一文字ずつフェード表示してから問題文を一文字ずつ表示し、続いて選択肢を1件ずつ、各選択肢の文も一文字ずつフェード表示する。表示中および上へ移動している間はノーツを出さず、タップも採点しない。全てが表示された後2.5秒待ち、パネル全体を0.65秒で画面上部へ移動する。読む時間は文字数から計算し、固定6秒制は廃止する。
4. 回答：パネルの上部への移動完了後に回答モードへ入り、4色のノーツを同じ時刻に横一列で流す。回答中は選択肢と同じ順序の4列とし、左から赤・青・黄・緑に固定する。4択は色と本文で表示し、色名や●・◆などの装飾記号は付けない。回答進捗の数値や回数用の行は表示せず、成功タップ数を必要回数で割った割合に応じて、選択肢全体の背景色を濃くする。選んだ色のノーツを、そのノーツがあるレーンで累計3回成功させると回答が確定する。ノーツが流れ始めるまで約1.8秒の準備時間がある。
5. 誤答：大きな✖️と「不正解 · もう一度」を1.5秒表示する。リズムの判定表示とは別枠にする。問題・選択肢の色割り当てを維持し、全色のカウントを0に戻して回答モードを継続。正解するまで次の問題に進まない。
6. 正解：大きな⭕️と「正解！」、正しい用語・補足説明を2.5秒以上表示する。正解確定時に残りの色ノーツを消し、新規ノーツを生成しない。正解タップの判定と正解表示を維持し、結果表示が終わってから次の？または通常プレイへ進む。
7. 通常プレイ：元問題のまとまりを解き終えたら、8主拍ぶん（現曲で約6〜7秒）の通常プレイ（白ノーツ数は120回目標に応じて調整）を挟んで次の問題へ進む。同じ説明文の次の穴と英単語の綴りを直接続ける場合だけ挟まない。最後のノーツも最後まで判定し、判定表示が終わってから切り替える。曲末に残りノーツが少ない場合は残りだけを使い、残りがなければ通常プレイを省略する。
8. 2曲目終了または「終了」でリザルト。スコア、最大コンボ、正解数、一発正解数、学習記録を表示する。2曲目終了時の未回答問題は誤答扱いにせず、未回答として表示する。

出題は履歴別の6カテゴリを重み付き抽選する。1プレイ中は既出問題と、一発正解した方向の逆問題を、他の候補がある限り除外する。同じ題材・方向で一度でも誤答した場合、その逆方向は通常の候補に残す。未出題候補を優先したうえで同じ題材の直近3単位を避け、間隔制限を緩めても候補がない時だけ既出・逆方向の除外を解除する。同じ説明文の複数穴、英単語の綴り、漢字部品は最後まで解き切る1単位とし、逆方向や熟語の別位置は他題材を挟んで選ぶ。候補が少ない範囲では題材の除外を緩和する。繰り返した回答もプレイ中の正解数に含む。回答履歴はこのブラウザに保存し、当回の学習記録と復習対象は結果画面で確認する。

## バージョン表示

トップ画面の冒頭右側に `v0.49.0` の形式でアプリのバージョンを常時表示する。PWAの接続・キャッシュ状態表示とは別にする。`package.json` の `version` を基準とし、公開更新の際に番号を上げてトップ画面とService Workerのキャッシュ名にも同じ値を反映する。

## 案内文

- 穴埋めは基本的に「『〇〇』の説明を完成させよう」とテーマを表示し、正答そのものを含む部分だけを伏せる。英語・漢字などに必要な手掛かりは維持する。
- 説明から用語を答える問題は「次の説明にあてはまる用語を選ぼう」を添える。
- 学習ゲームの文体として「〜しなさい」よりも「〜しよう」を採用する。

## 出題方向・穴埋め

- 解説→用語：全穴を正解で埋めた説明文から、正しい用語を4択で選ぶ。
- 用語→解説：説明文と必要な場合のみ文脈を示し、指定された1つの穴に入る語句を4択で選ぶ。その穴の `answer` と `dummies` を使用し、別の穴の候補を混ぜない。
- 複数穴は `blanks[].index` の昇順で1つずつ出題。本文の未回答部分は全て `？` とし、対象の `？` を背景と下線で強調する。「強調された？に入る語句を回答（1 / 2）」「次の？に入る語句を回答（2 / 2）」と進捗を示し、「穴1」「穴2」の表記は使わない。正解済みの部分は正しい語句で埋める。
- 同じ説明文の次の `？` は連続回答する。パネルを上部に保持し、正解済みを残しながら強調と選択肢を切り替える。本文の文字送りと上下移動は繰り返さず、新しい選択肢だけを順次表示してから2.5秒の確認時間を確保する。
- 「解説→用語」「用語→解説」などの形式名は画面・学習記録に出さない。用語を表示する問題では用語を含む案内文を表示し、説明から用語を選ぶ問題には具体的な操作の案内を添える。
- 各穴で累計3回のタップによる回答確定・誤答時の再挑戦・正誤表示を行う。誤答では同じ穴に留まり、正解後の結果表示が終わってから次の穴へ進む。全穴の正解後に別題材へ進む。補足解説は最後の穴の正解時に表示し、途中の穴では後続の正解を明かさない。
- 得点・一発正解コンボ・正解数は穴ごとに集計し、穴を切り替えると回答進捗を0に戻す。学習記録には用語・「？（2 / 2）」のような進捗・正解を残し、2曲目終了時の未回答も同じ表記で明示する。
- 現データ89件から、用語回答89問と穴埋め97問の計186問を生成する。2方向と各穴を同じ題材として管理し、別の題材を挟んで配置する。

## ノーツ・入力

- 色ノーツは毎主拍、白ノーツは主拍を基本に見逃しも含む120回分の目標に合わせて増減し、必要時は拍の間にも追加する。譜面の `beatPosition === 0` の主拍を小節・拍番号ごとに1件選び、元の時刻を保持する。元データ605イベントのうち450件を使用（120 BPMで概ね0.5秒に1回）。カラーはこの主拍間隔を使い、白は必要時のみ中間拍を追加する。出題・移動中はノーツを生成しない。
- 全場面で常時4レーン。フェーズによってレーン数を変更しない。ノーツは上から下へ1.8秒で移動し、手前の判定ラインでタップする。
- 白ノーツ：1回につき1レーンだけに生成し、そのレーンへの入力だけを成功判定する。4レーンを1回ずつ含む組を毎回シャッフルし、出現レーンの偏りを抑える。密度は主拍を基本に120回目標に合わせて増減する。
- 色ノーツ：4色全てを毎回同時刻に横一列で出す。選択肢と同じ左からの順序で、色の位置は入れ替えない。画面内タッチ、下部の4ボタン、D/F/G/Hキーで選択。全場面で同じ4キーを使用。通常プレイの一時停止・再開は不可。
- 1列につき1色だけ選択できる。1色に成功すると同じ列の残り3色も消え、追加の回答進捗・得点は入らない。4色全てをタップする必要はない。次の列で再び選べる。
- 出題中（下部表示から上への移動完了まで）はタップ不要。入力を無視し、空振りやコンボ切断にもならない。音楽はそのまま再生する。「タップお休み」などの案内は表示しない。
- 選択肢・色ノーツとも装飾記号は付けず、4色の固定位置と選択肢本文で対応を示す。色名の繰り返し表示はしない。選択肢の直接クリックでは回答できない。
- プレイ画面全体で文字選択、長押しのメニュー、ドラッグを抑止する。タップエリアはブラウザのタッチジェスチャーを無効にし、連打で選択ハンドルが出ることを防ぐ。
- 文字表示・上への移動も音源の再生位置で進行する。1文字180ms間隔、フェード650ms、選択肢間の待ち時間1.2秒。全表示後の読了待ちは2.5秒。問題文・選択肢の文字送りを前回の2倍ゆっくりにする。新しい問題ごとに演出を開始し、誤答時は繰り返さない。OSの動きの軽減設定時はフェード・滑らかな移動を省略するが、同じ順序・待ち時間を保持する。
- PERFECTは判定中心（目標時刻）±80ms、GOODは同じ中心の±160ms、範囲外・別レーンへのタップはMISS。判定対象が重なる場合は同一レーンで時刻が最も近い1件を消費する。
- 白ノーツの見逃し・空振り、4色の列を1色も選ばず見逃した場合は「MISS」を表示してリズムコンボを0にする。4色1列の見逃しは1回として扱う。選択成功後の残り3色は見逃し扱いにしない。クイズの進捗や一発正解の判定はリズムのMISSでは失わない。
- PERFECT・GOOD・MISSは判定ライン付近の専用表示で0.9秒表示し、クイズの正誤表示に上書きされない。判定は音源の時計に従う。
- 画面非表示・フォーカス離脱・音楽中断時は途中終了とし、通常プレイは再開できない。チューニングのみ停止後の明示再開を許す。
- 正解確定以外のフェーズ変更では未判定ノーツを消去しない。ウォームアップは判定幅と判定表示時間まで含めて8秒内に完了するイベントだけを生成する。正解後は新規生成を停止し、残りの色ノーツを直ちに消す。消したノーツはMISSや加点の対象にせず、結果表示が完了してから次へ進む。回答開始後1.8秒以内のイベントは準備時間として生成しない。描画が遅れて判定時間を過ぎたイベントも、無言で捨てずMISSにする。

## スコア・コンボ

現行の満点は10,000点（白5,000＋カラー1,000＋正答4,000）。開始時の一発正解基準プレイの白数W・加点対象カラー列数C・問題段階数Nから配点する。実際の数が増えた場合は大きい方を分母にする。途中の得点は暫定値。旧点数との合計スコア自己ベストは分ける。

| 分類 | 加点 | コンボ |
| --- | --- | --- |
| 白 | PERFECTは5,000/W点、GOODはその50％、見逃し0点 | 成功+1。見逃し・空振り・誤答確定で0 |
| カラー | 各回答段階の最初の必要列数のみ、PERFECTは1,000/C点・GOODはその50％・見逃し0点。以後0点 | 0点でも成功+1、MISS・誤答確定で0 |
| 正答 | 一発4,000/N点。お手つき1回80％、2回50％、3回以上0点 | 一発正解ごと+1、誤答確定で0 |

コンボ表示・記録は維持し、旧コンボ数の加点は行わない。空振りは120枠を消費せず、白＋カラーの得点に判定済み数／（判定済み数＋空振り数）を掛けて減点する。
必要数未満の色タップは回答の確定ではない。たとえば赤1回・青3回で青を回答した場合、それ以前に確定した誤答がなければ一発回答に該当する。色ごとの進捗は独立に蓄積し、ミスタップ・見逃しでは進捗を失わない。

## JSONデータの理解と利用

### quiz-data/junior_science.json

配列89件。全て `school_level: 中学`、`grade: 中3`、`subject: 理科`。81件が1穴、8件が2穴。

| キー | 意味・仮実装での扱い |
| --- | --- |
| id | 問題の識別子 |
| subject / school_level / grade / field / unit | 科目・学校段階・学年・分野・単元。現在は学年・科目・分野を表示 |
| term / term_dummies | 正解用語と誤答候補。同じ概念群の紛らわしい誤答3件を問題ごとに保持し、正解を含む4択をシャッフル |
| explanation_template | `{{1}}` 等を含む説明文 |
| blanks[].index / answer / dummies | 穴の番号・正解・誤答候補。穴埋め形式では各穴の正解と候補を使用し、同じ説明文の複数穴は番号順に最後まで連続回答する。用語回答形式では全穴を正解で埋める |
| difficulty.term_to_explanation / explanation_to_term | 出題方向ごとの難度。仮実装ではフィルタに使わない |
| note | 正解後・リザルトに表示する補足説明 |

JSONは完成した4択問題そのものではなく、出題方向を変えられる素材と理解している。採用方向は `explanation_to_term` と、穴埋めで回答する `term_to_explanation` の両方。今回、用語89問と穴埋め97問の誤答候補を各3件に見直した。候補をジャンル横断で自動補充するのではなく、同じ分野・実験操作・計算の取り違えを中心に手動で選定する。選択肢の文法や語尾を揃え、正解の同義語が誤答に入らないようにする。詳細は [問題データの編集方針](../quiz-data/README.md) を参照。

### music-data/index.json と楽曲JSON

楽曲ID `0001` は先頭の0を保持する文字列。MP3・JSON・MIDIのパスはインデックスから解決する。

- Fallin For You / Flehmann、120 BPM、233.0672秒。
- JSONの `events` は605件（beat 337、downbeat 113、offbeat 155）。`time` はMP3先頭からの秒。
- `bar`、`beatInBar`、`accent`、`velocity`、`intensity` 等は音楽上のメタデータ。時刻と小節・拍のメタデータを採用し、強さによる得点差は付けない。
- `noteMapping` / `noteNumber` は音符番号であり、画面の回答色やレーン指定とは解釈しない。一部イベントは `noteNumber` がないが `time` による処理には問題ない。
- レーン・回答色が未定義のため、間引き後のイベント時刻ごとに4色を同時生成する。回答列は左から色インデックス0〜3で固定し、選択肢と対応させる。問題の正解色に依存しない。
- `source` のファイル名と実ファイル名は異なる。アセット参照は必ず `index.json.files` を使う。
- MIDIは参考データであり、実行時の再生・解析には使わない。

時刻の契約:

```js
const targetSeconds = event.time
  + (track.timing.chartToAudioOffsetMs + deviceOffsetMs) / 1000;
```

MP3の `audio.currentTime` を表示・判定・フェーズ進行の唯一の時間基準とする。`offsetSeconds: 0.11733` と `syncCorrectionMs` はイベントに適用済みであり、再加算しない。曲別補正は0msの暫定値で、音声の拍との独立検証は未実施。詳細は [音楽データ管理](../music-data/README.md) を参照。

端末補正はホームの手動設定またはチューニングで±500msを指定し、このブラウザのlocalStorageに出力別に保存する。正でノーツと判定対象時刻を遅らせる。音声出力は自動識別しないため、Bluetooth等を切り替えた場合は保存済み出力を選び直す。

## PWA・技術構成

依存パッケージなしのHTML/CSS/JavaScript ModulesとCanvas。Web App Manifest、192/512pxアイコン、Service Workerを持つ。

初回のService Workerインストール時にアプリ・問題・楽曲インデックス・譜面をキャッシュし、音源は有効化後に別キャッシュへ保存する。音源の保存完了をOFFLINE READYとして表示し、その後にオフライン再起動・音声再生が可能。音声のRangeリクエストにもキャッシュから206応答する。初回オフラインやキャッシュ削除後は利用不可。ブラウザによるキャッシュ削除の可能性もある。更新時は `sw.js` のキャッシュバージョンを上げる（今回はv0.49.0）。更新用アセットはHTTPキャッシュを再検証し、旧版が混ざることを防ぐ。新しいService Workerに切り替わった際、ホームでは自動再読込し、プレイ中は中断せず更新案内を表示する。

ローカル起動はlocalhost、本番はHTTPSが必要。PWAインストール操作・対応状況はブラウザに依存する。

#### 学習目的と対象範囲

- 既存の知識暗記に加え、解き方の重要な判断・注目箇所・使える条件・誤りやすい点を反復する。紙・鉛筆を必要とする計算や長文の解答完遂を通常プレイの中心にしない。短い具体例の中で、使うポイントを選ぶ問題を組み合わせる。
- 国語：指示語の候補を置き換えて確認する、主張と具体例を区別する、選択肢の言い過ぎ・範囲のずれを確認する等の読み方。
- 英語：語順・文の構造・動詞等の形を判断する手掛かり。関係代名詞と間接疑問文は別の学習事項として扱う。
- 数学：操作の選び方、符号、公式の適用条件、誤った途中式の見分け。用語名を答えさせる方向には戻さず、複雑な暗算を要求しない。表から一次関数の式を計算する擬似例は採用せず、傾きや切片をどう読み取るか等のポイント確認へ変更する。図形も数値の算出だけでなく、使う関係や式を選ぶ形式を中心にする。
- 理科：実験条件のそろえ方・結果の見方・計算式の使い方。社会：資料で注目する項目・比較の基準・因果関係の捉え方。

#### 問題単位と内容検証

- 同じ学習ポイントに、複数の表現・題材・簡単な数値のパターンを用意し、出題済み数や優先度は共通の問題単位で集計する。内部にはどのパターンを出したかも保持し、未出題・古いパターンを選べる設計とする。
- 『指示語』全体などの大分類を1問にまとめず、確認する判断段階が同じになる粒度で問題を定義する。例：直前の語句／前の一文／複数文を指す指示語は別の問題単位。

- 正解後の解説は正答の言い換えだけでなく、根拠・注意点・誤りやすい点を短く示す。解説画面の量と時間はサンプルで確認してから確定する。
