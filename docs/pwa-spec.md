# Study Beat PWA 仕様書（仮実装）

更新日: 2026-10-30

## 目的・対象

中学生・高校生が、音楽に合わせたタップと4択クイズを通して楽しく暗記を繰り返す学習用音楽ゲーム。リズムの上達と知識の定着を別々に評価する。

既存のリズムゲーム仕様を、暗記学習用の仕様に更新し、静的PWAを追加した。現サンプルは中3理科89件、1曲。対象全体は中高生だが、高校問題データはまだ含まない。

## ゲームの流れ

1. ホームで遊び方・収録曲を確認して開始。初回は問題・音楽データを読み込む。
2. ウォームアップ（暫定8秒）：5レーンを横断する白ノーツを、どのレーンでもタイミングよくタップ。
3. 出題：問題文と4択のパネルを手元（判定ラインの上）に表示。問題文を一文字ずつフェード表示し、続いて選択肢を1件ずつ、各選択肢の文も一文字ずつフェード表示する。表示中は横長の白ノーツを続ける。全てが表示された後0.8秒待ち、パネル全体を0.65秒で画面上部へ移動する。読む時間は文字数から計算し、固定6秒制は廃止する。
4. 回答：パネルの上部への移動完了後に回答モードへ入り、色付きノーツを5本のレーンに流す。4択を赤●・青◆・黄▲・緑■に対応させるが、選択肢には色名を記載せず、色と記号・選択肢本文を表示する。選んだ色のノーツを、そのノーツがあるレーンで累計3回成功させると回答が確定する。ノーツが流れ始めるまで約1.8秒の準備時間がある。
5. 誤答：問題・選択肢の色割り当てを維持し、全色のカウントを0に戻して回答モードを継続。正解するまで次の問題に進まない。
6. 正解：正しい用語・補足説明と結果を暫定2.5秒表示し、次の問題へ。ノーツは白に戻る。
7. 曲終了または「終了」でリザルト。スコア、最大コンボ、正解数、一発正解数、学習記録を表示する。曲終了時の未回答問題は誤答扱いにせず、未回答として表示する。

問題は毎回シャッフルし、一巡したら先頭から繰り返す。繰り返した回答もプレイ中の正解数に含む。学習記録はそのプレイ中のみ保持する。

## ノーツ・入力

- 4拍のうち1拍だけにノーツを出す。現在の4/4曲では、譜面の `beatInBar === 1 && beatPosition === 0` を小節ごとに1件選択し、元の時刻を保持する。元データ605イベントのうち112件を使用（120 BPMで概ね2秒に1回）。全フェーズで同じ密度とし、裏拍は出さない。
- 暫定5レーン。ノーツは上から下へ1.8秒で移動し、手前の判定ラインでタップする。
- 白ノーツ：全レーン横断。位置を問わず1回の入力で1ノーツを判定する。
- 色ノーツ：単一レーン。画面内タッチ、下部のレーンボタン、D/F/G/H/Jキーに対応。Spaceで一時停止・再開。
- 色と記号を併用し、色だけに依存させない。色名の繰り返し表示はしない。選択肢の直接クリックでは回答できない。
- プレイ画面全体で文字選択、長押しのメニュー、ドラッグを抑止する。タップエリアはブラウザのタッチジェスチャーを無効にし、連打で選択ハンドルが出ることを防ぐ。
- 文字表示・上への移動も音源の再生位置で進行し、一時停止中は演出も停止する。1文字35ms間隔、フェード200ms、選択肢間の待ち時間180ms。新しい問題ごとに演出を開始し、誤答時は繰り返さない。OSの動きの軽減設定時はフェード・滑らかな移動を省略するが、同じ順序・待ち時間を保持する。
- PERFECTは目標時刻±80ms、GOODは±160ms、範囲外は空振り。判定対象が重なる場合は同一レーンで時刻が最も近い1件を消費する。
- 白ノーツの見逃し・空振りはリズムコンボを0にする。色ノーツは選ばない色を避ける必要があるため、見逃しではコンボを切らない。
- 画面非表示時は音源を停止する。再開は明示操作とし、経過時間を先へ飛ばさない。
- フェーズ変更時は旧フェーズの残ノーツを消去し、ペナルティなしとする。変更後1.8秒以内のイベントは生成せず、以前の色・問題のノーツが混ざることを防ぐ。これは試作向けの切替方法であり、演出は後日改善する。

## スコア・コンボ

| 分類 | 加点 | コンボ |
| --- | --- | --- |
| リズム | PERFECT 100点、GOOD 50点。白・色とも同じ | タップ成功ごとに+1。白の見逃し・空振りで0 |
| 学習 | 最初に確定した回答が正解なら1,000点。誤答後の正解は0点 | 一発正解の問題ごとに+1。回答が誤答で確定すると0 |

必要数未満の色タップは回答の確定ではない。たとえば赤1回・青3回で青を回答した場合、それ以前に確定した誤答がなければ一発回答に該当する。色ごとの進捗は独立に蓄積し、ミスタップ・見逃しでは進捗を失わない。

## JSONデータの理解と利用

### quiz-data/junior_science.json

配列89件。全て `school_level: 中学`、`grade: 中3`、`subject: 理科`。81件が1穴、8件が2穴。

| キー | 意味・仮実装での扱い |
| --- | --- |
| id | 問題の識別子 |
| subject / school_level / grade / field / unit | 科目・学校段階・学年・分野・単元。現在は学年・科目・分野を表示 |
| term / term_dummies | 正解用語と誤答候補。候補は重複を除いて3件選び、正解を含む4択をシャッフル |
| explanation_template | `{{1}}` 等を含む説明文 |
| blanks[].index / answer / dummies | 穴の番号・正解・誤答候補。仮実装では全穴を正解で埋め、説明から用語を選ばせる。穴埋め自体の出題には未使用 |
| difficulty.term_to_explanation / explanation_to_term | 出題方向ごとの難度。仮実装ではフィルタに使わない |
| note | 正解後・リザルトに表示する補足説明 |

JSONは完成した4択問題そのものではなく、出題方向を変えられる素材と理解している。現状の採用方向は `explanation_to_term`。誤答候補数が4件あっても、4択では3件のみ採用する。

### music-data/index.json と楽曲JSON

楽曲ID `0001` は先頭の0を保持する文字列。MP3・JSON・MIDIのパスはインデックスから解決する。

- Fallin For You / Flehmann、120 BPM、233.0672秒。
- JSONの `events` は605件（beat 337、downbeat 113、offbeat 155）。`time` はMP3先頭からの秒。
- `bar`、`beatInBar`、`accent`、`velocity`、`intensity` 等は音楽上のメタデータ。時刻と小節・拍のメタデータを採用し、強さによる得点差は付けない。
- `noteMapping` / `noteNumber` は音符番号であり、画面の回答色やレーン指定とは解釈しない。一部イベントは `noteNumber` がないが `time` による処理には問題ない。
- レーン・回答色が未定義のため、間引き後のイベント順を使い `index % 5` でレーン、回答モードでは `index % 4` で色を割り当てる。問題の正解色に依存しない。
- `source` のファイル名と実ファイル名は異なる。アセット参照は必ず `index.json.files` を使う。
- MIDIは参考データであり、実行時の再生・解析には使わない。

時刻の契約:

```js
const targetSeconds = event.time
  + (track.timing.chartToAudioOffsetMs + deviceOffsetMs) / 1000;
```

MP3の `audio.currentTime` を表示・判定・フェーズ進行の唯一の時間基準とする。`offsetSeconds: 0.11733` と `syncCorrectionMs` はイベントに適用済みであり、再加算しない。曲別補正は0msの暫定値で、音声の拍との独立検証は未実施。詳細は [音楽データ管理](../music-data/README.md) を参照。

端末補正はホームの設定で±500msを指定し、このブラウザのlocalStorageに保存する。正でノーツを遅らせる。音声出力の自動識別・出力別の設定保存は未実装で、Bluetooth等を切り替えた場合は手動で再調整する。

## 不明瞭な点・暫定判断

ユーザー指定済みの方向を実装可能にするための仮定であり、以下は確定仕様ではない。

| 項目 | 仮実装 | 確認・今後決めること |

| レーン数 | 5本 | 「5本？」の最終決定 |
| 回答の必要タップ | 各色累計3回、誤答で全色リセット | 連続同色とするか、問題別・難度別に変えるか |
| 出題アニメーション | 文字数に応じて順次表示、全表示後に上へ移動 | 文字送り速度・読了待ち時間の調整 |

| 正解後の学習点 | 一発正解のみ1,000点 | 再挑戦の正解にも学習点を付けるか |
| 見逃し | 色ノーツはペナルティなし | 色の選択とリズム評価を両立する難度設計 |

| コンテンツ | 中3理科89件のみ | 中1・2、高校、他科目のデータ追加 |

`difficulty` の2方向は理解できるが、用語から説明を選ぶための完成した誤答説明は現データにない。穴の誤答候補を入れ替える方法は考えられるが、複数穴では文全体の妥当性の確認が必要。

## PWA・技術構成

依存パッケージなしのHTML/CSS/JavaScript ModulesとCanvas。Web App Manifest、192/512pxアイコン、Service Workerを持つ。

初回のService Workerインストール時にアプリ・問題・楽曲インデックス・譜面・MP3をまとめてキャッシュする。完了後にオフライン再起動・音声再生が可能。音声のRangeリクエストにもキャッシュから206応答する。初回オフラインやキャッシュ削除後は利用不可。ブラウザによるキャッシュ削除の可能性もある。更新時は `sw.js` のキャッシュバージョンを上げる（今回はv2）。更新用アセットはHTTPキャッシュを再検証し、旧版が混ざることを防ぐ。新しいService Workerに切り替わった際、ホームでは自動再読込し、プレイ中は中断せず更新案内を表示する。

ローカル起動はlocalhost、本番はHTTPSが必要。PWAインストール操作・対応状況はブラウザに依存する。
