# リズムゲームPWA仕様

本書は会話で合意した仕様と今後決める事項を管理します。未決定事項を確定仕様として実装せず、実装時に決定内容を本書へ反映してください。

## 目的と基本動作

MP3音源のリズムに合わせてユーザーがタップするPWAを構築します。楽曲は今後も追加します。

楽曲一覧には楽曲名と作成者を表示する想定です。楽曲データの取得元は `music-data/index.json` とし、IDは先頭の0を保持する文字列として扱います。楽曲ファイルは `music-data/<楽曲ID>/` に格納します。詳細な登録・検証ルールは [音楽データ管理ルール](../music-data/README.md) に従ってください。

## 音源と譜面

- 音源はMP3を使用します。
- 実行時のタップ譜面はJSONを採用する方針です。MIDIは編集・交換用として保持し、ゲーム実行に必須としません。
- JSONの `events[].time` はMP3先頭からの秒数として読み込みます。BPMからイベント時刻を再生成しません。これにより、イベント時刻に反映済みのテンポ変化や局所補正を保持します。
- インデックスの `baseBpm` は基本値であり、曲全体のテンポが一定であることを保証しません。曲の長さは `durationSeconds` で保持します。
- 読み込み時に必須項目・数値・イベント時刻の順序などを検証します。譜面形式のバージョン管理方法と検証規則の詳細は未決定です。

## 再生と同期

MP3の再生位置を基準に描画とタップ判定を行います。音源と譜面を独立したタイマーで走らせません。HTMLAudioElementを使う場合は `currentTime`、Web Audioを使う場合は音源開始時刻と同じAudioContextの時計を基準にします。採用する再生APIは未決定です。

フレーム描画やタイマーの発火時刻だけに判定精度を依存させず、入力時刻を音源と共通の時間基準へ変換して判定します。具体的な入力時刻の変換方式は実装時に検証します。

## 曲ごとの補正

曲全体の一定のズレは `music-data/index.json` の各曲の `timing.chartToAudioOffsetMs` にミリ秒で保持します。正なら譜面を遅らせ、負なら早めます。譜面JSONに同じ追加補正を重複保存しません。

曲途中で変わるズレはイベント時刻側で補正します。譜面に既に適用済みの開始位置補正や局所補正を再加算しません。追加補正を譜面時刻へ焼き込む場合は、インデックスの値をリセットまたは再計測します。

新曲の事前検証では、音源と譜面の冒頭・中盤・終盤を確認し、一定のズレと途中で変わるズレを区別します。MIDIとJSONの一致確認と、音源の拍との一致確認は別々に記録します。補正値が0でも検証済みを意味せず、未検証・暫定の状態を明記します。

現在の0001（Fallin For You / Flehmann）はMIDI・JSON間の605イベントの一致を確認済みで、最大時刻差は0.52ミリ秒です。音源の拍との一致は独立に検証できていないため、追加補正0ミリ秒は暫定値です。

## ユーザーのタイミング調整

設定画面でユーザーが端末依存のズレをミリ秒単位で調整できるようにします。曲側の補正とは別に保存し、再起動後も保持します。楽曲インデックスに個人設定を書き込みません。

同じ端末でもスピーカー・有線イヤホン・Bluetoothで遅延が変わるため、出力先を変えた際に再調整できるようにします。保存方式、出力先別プロファイル、調整範囲、操作刻み、自動調整の有無は未決定です。

補正値の符号は曲側と統一し、正なら判定対象時刻を遅らせます。基本式は次のとおりです。

```js
const songOffsetMs = track.timing.chartToAudioOffsetMs ?? 0;
const targetAudioTimeSeconds = event.time + (songOffsetMs + deviceOffsetMs) / 1000;
const errorMs = (inputAudioTimeSeconds - targetAudioTimeSeconds) * 1000;
```

`deviceOffsetMs` はPWAのユーザー設定、`inputAudioTimeSeconds` は入力時刻を音源の時間軸へ変換した値です。同じ補正を入力時刻・イベント時刻の両方へ重複適用しません。描画への端末補正の反映方法や視覚補正の独立設定は未決定です。
